# design-doc-readability

An agent skill that grades a design doc for human readability and writes a
score card. It measures how close the prose is to the plain style of IETF
RFCs and the Kubernetes architecture docs, and how often it uses the habits
of text generated by a language model. It applies the technical writing
standards of the Utah State University (USU) Engineering Writing Center.

The skill is in the Agent Skills format: a `SKILL.md` file with a name and a
description, plus the files it references. The skill has been tested with
Claude Code and OpenAI Codex. Gemini CLI reads skills in this format from
the same directory as Codex, but the skill hasn't been tested with it yet.

The grade is about prose, not about the design. The skill never edits the
doc.

## What it produces

A score card for one doc, with nine axes scored from 0 to 10:

| Axis | Weight | What it measures |
| --- | --- | --- |
| Vocabulary | 15 | Words a model reaches for, such as "delve", "leverage", and "seamless", and inflated words such as "utilize" |
| Filler | 10 | Phrases that frame instead of saying something, redundancies, and wordy phrases |
| Rhetoric | 15 | Contrasts such as "It's not X, it's Y", reveals, fragment chains, and rhetorical questions |
| Tone | 10 | Hype, intensifiers, opinion, and chat residue |
| Typography | 10 | Em dashes, bold, emoji, and arrows in prose |
| Structure | 10 | Bullets where paragraphs belong, bold-label bullets, and long sentences and paragraphs |
| Precision | 10 | Hedges and vague words, against numbers, limits, and stated requirements |
| Terminology | 10 | Defined terms, one name per concept, and acronyms spelled out |
| Economy | 10 | Repetition, and sentences that stack clauses |

The overall score is the weighted mean, from 0 to 100:

| Score | Grade | Meaning |
| --- | --- | --- |
| 90 to 100 | A | Reads like an RFC. |
| 80 to 89 | B | Plain, with a few habits a careful reader notices. |
| 70 to 79 | C | The habits are frequent enough to slow a reader. |
| 60 to 69 | D | Reads as lightly edited model output. |
| 0 to 59 | F | Reads as unedited model output. |

The score card also quotes the three to five worst passages with a rewrite
for each, and lists the fixes that would raise the grade most.

## How it works

1. A scanner, `scripts/scan.py`, measures the first seven axes. It matches
   the patterns in `scripts/patterns.json` and reports each as a density
   per 1,000 words, with the line of each hit. It ignores code, URLs, front
   matter, and template shortcodes. It needs only Python 3.
2. The agent reads the whole doc against the rubric in
   `references/rubric.md`. It can move each measured score by up to 3
   points, with a reason and a line number, and it scores terminology and
   economy by reading.
3. The agent writes the score card in a fixed format.

The scanner finds only what a regular expression can find. Recent models
avoid the well-known word list and still write prose that reads as
generated, so the reading in step 2 is required.

## Install

Clone the repository, and link the skill into each agent's skills
directory:

```sh
git clone https://github.com/hsnodgrass/design-doc-readability.git
cd design-doc-readability

# Claude Code
mkdir -p ~/.claude/skills
ln -s "$PWD/skills/design-doc-readability" ~/.claude/skills/design-doc-readability

# Codex and Gemini CLI
mkdir -p ~/.agents/skills
ln -s "$PWD/skills/design-doc-readability" ~/.agents/skills/design-doc-readability
```

A link keeps each agent on the checked-out version, so `git pull` updates
all of them. Copy the directory instead if you want a fixed version.

## Use

Ask the agent to grade a doc:

```text
Grade docs/token-refresh.md for readability.
```

In Claude Code, you can also run `/design-doc-readability docs/token-refresh.md`.
The doc can be a local file, a URL, or text you paste. The agent saves a URL
or pasted text to a temporary file before it grades it.

You can run the scanner on its own:

```sh
python3 skills/design-doc-readability/scripts/scan.py docs/token-refresh.md
python3 skills/design-doc-readability/scripts/scan.py --json --max-hits 10 docs/token-refresh.md
```

## The standard

The skill grades against three sources:

- IETF RFCs, for specifications: https://www.rfc-editor.org/
- The Kubernetes architecture docs, for explanation:
  https://kubernetes.io/docs/concepts/architecture/
- The USU Technical Writing Standards and Style Guidelines, for the rules
  of technical prose:
  https://engineering.usu.edu/students/engineering-writing-center/writing-resources/technical-writing-standards

The scanner's thresholds were set from 10 RFCs and the 10 Kubernetes
architecture pages, and checked against 19 design docs from a private
repository and a fixture written in heavy LLM style. The RFCs score 99 to
100, the Kubernetes pages have a median of 97, and the fixture scores 0.
`references/calibration.md` has the numbers and the steps to recalibrate.

## Tuning

The patterns, their weights, the score thresholds, and the list of
well-known acronyms are in `scripts/patterns.json`. After you change them,
run `scripts/calibrate.py` over a set of docs you trust and a set you
don't, and check that the scores still separate them. Never commit a
calibration corpus that holds private docs. The `.gitignore` excludes
`corpus/` for that reason.

## Layout

```text
LICENSE                  The Apache License, Version 2.0
skills/design-doc-readability/
  LICENSE                A copy of the license, for copies of the skill alone
  SKILL.md               The skill's instructions
  references/
    rubric.md            How to score each axis
    patterns.md          The patterns, with examples and rewrites
    calibration.md       The calibration data and how to recalibrate
  scripts/
    scan.py              The scanner
    patterns.json        The pattern catalog and thresholds
    calibrate.py         Prints the scanner's results over a set of docs
tests/
  test_design_doc_readability.py
  fixtures/              An LLM-heavy doc and an RFC-like doc
```
